# 前端说明（Vue 3 + Ant Design Vue + Leaflet + ECharts）

> 目录：`frontend/`　开发端口：`5173`　构建产物：`frontend/dist/`

## 1. 技术选型

| 关注点 | 选型 | 理由 |
| --- | --- | --- |
| 框架 | Vue 3.5（Composition API + `<script setup>`） | 与 Ant Design Vue 4 天然匹配，模板语法对新手友好 |
| UI 组件库 | **Ant Design Vue 4** | 后台管理场景组件最全（表格/表单/抽屉/时间线/统计卡），中文本地化开箱可用 |
| 构建 | Vite 6 | 冷启动秒级；原生 ESM；配置量极小 |
| 语言 | TypeScript（`strict`） | 接口字段多，类型能在编译期挡住大部分"字段名写错"的低级错误 |
| 路由 | Vue Router 4（history 模式） | URL 干净，可直接分享 `/orders` 这类链接 |
| 地图 | Leaflet 1.9 + 中国省级 GeoJSON + 自研程序化瓦片 | 中国地图提供方位锚点；真实城市路网提供尺度感；两者都**不请求在线底图服务**（内网/断网可用） |
| 图表 | ECharts 5（**按需引入**） | 国内生态成熟；按需引入后体积从 ~1MB 降到几十 KB |
| 状态 | 模块级 `ref` 单例（`store/telemetry.ts`） | 状态本质是"服务端推送的镜像"，无需 Pinia 的复杂度 |

**没有引入的东西及原因**：没有 axios（原生 fetch 够用）、没有 Pinia（见上）、没有 ESLint/Prettier（避免给学习者增加工具链负担，代码风格靠注释与约定统一）、没有 unplugin 按需引入（内部后台不敏感于体积，全量注册组件让模板更干净）。

## 4. 页面说明

### 4.1 实时看板 `/`

三屏信息密度递增：

1. **KPI 卡片**：订单总数 / 待派单 / 配送中 / 已送达 / 活动无人机 / 平均电量 / 准时率 / 未处理冲突。
   带语义色条：异常值（待派单积压、电量偏低、有冲突）会变成红/黄色左边框。
2. **空域态势地图 + 结构分布图**：地图分三层（空域垫底、航路居中、无人机最上）；
   右侧是订单状态环形图与机队电量分布柱状图。
3. **机队实时状态表 + 冲突/事件面板**：表格按"在飞的排前面"排序；点表格行或点地图上的飞机会双向联动。

### 4.2 订单管理 `/orders`

- 按状态/优先级筛选，服务端分页；
- **新建订单**弹窗：含起终点经纬度、优先级、期望送达时间，并在提交前实时算出**直线距离**
  提示"无人机需往返，实际航程约为其 2 倍以上"——避免下出飞不到的单；
- **派单**：按钮 + 策略下拉（最近可用 / 电量优先 / 负载均衡），策略直接影响派给哪架飞机；
- **决策明细**抽屉：展示本次派单对**全部无人机**的评估结果——排名、得分、是否选中、淘汰原因，
  展开行还能看到分项指标 JSON。这是把"调度黑盒"变透明的入口。
- **批量派单**：指定策略与条数，一次性扫单。

### 4.3 任务管理 `/tasks`

- 任务列表（状态、进度条、计划/实际航程、预计/实际能耗、耗时）；
- **详情抽屉**：任务字段 + 航路点表格（画航迹/核对绕障）+ 事件时间线（回放与归因）；
- 一键导出该任务的**遥测 CSV** 与**事件 CSV**；
- 中止任务（未起飞的中止后订单回到待派队列，已在飞的中止后订单置为失败）。

### 4.4 机队管理 `/drones`

机型能力（载重/速度/续航/能耗）、实时电量进度条、位置、当前任务、累计里程与飞行时长；
注册新机、手动改状态（充电/维护/下线）。

注册弹窗里选完机型后会显示一张**只读能力卡**：最大载重、巡航速度、电池/能耗，
以及三个由机型参数算出来的关键结论 —— **满电航程**（电池容量 ÷ 每公里能耗）、
**可用往返半径**（扣掉 25% 安全冗余后往返可覆盖的单程距离）、标称最长飞行时间。
不显示航程的话，"选机型"就只能盲选：运营看得到型号代码，却不知道这架机能覆盖多远。
数据直接取自已加载的无人机列表（`DroneDtos.Response` 本就带机型能力），不额外加接口。

#### 整机解析：从"看个外形"到"看清每个零件为什么存在"

表格行末的「整机解析」打开一个 1240px 宽的弹窗，含两个页签：

| 页签 | 回答的问题 | 实现 |
| --- | --- | --- |
| **整机结构图谱** | 这架飞机里到底有什么、每个零件干什么 | `DroneAnatomy.vue` + `droneAssembly.ts` |
| **装载过程演示** | 它怎么干活（抓货、起飞） | `DroneModel3D.vue`（原有的五阶段动画） |

结构图谱不是"一张好看的爆炸图"，它要同时解决两件事：

1. **看得进去**：模型按零件拆分建模（一架 X4 约 43 个零件、200 余个网格），
   每个零件是独立分组、独立材质，所以能：
   - **拆解**（0–100% 滑杆）：零件沿各自方向散开，露出电池、飞控、电调、锁钩这些内部件；
   - **透视**：上下壳体半透明，隔着一层壳看内部布局；
   - **独显**：选中一件，其余降到 5% 不透明度，只看它；
   - **引线标注**：挂牌排在模型外侧两列（工程图习惯），引线指向零件本体。
2. **读得懂**：右侧清单按 **结构 / 动力 / 航电 / 任务载荷 / 安全** 五个系统分组，
   选中任意零件给出四段说明 —— **作用（一句话）→ 怎么工作/坏了会怎样 → 关键规格 → 与调度的关系**。

最后一段是这个视图存在的理由：纯展示的爆炸图看完只记得"零件很多"，
把零件接回业务规则（电池 → 航程约束、电机拉力 → 载重校验、锁钩 → 送达回执、降落伞 → 航线上报），
这张图才解释得了"调度系统凭什么这么派单"。机型能力参数与后端 `drone_model` 表严格一致，
避免"画面讲一套、派单算一套"。

> 技术上有两个坑记在这里：
> ① 相机取景必须按**包围盒实时算**（`boundsOf()`），写死距离会导致拆解后零件飞出画面；
> ② `Vector3.normalize()` 返回的是自身，把常量方向向量拿去 `multiplyScalar()` 会就地改掉它 ——
> 之后所有"按单位向量算距离"的地方都会偏，这个 bug 排查了很久，现在统一用 `addScaledVector`。

### 4.5 空域管理 `/airspace`

禁飞区 / 限飞区 / 走廊的增删，圆形（圆心+半径）与多边形（≥3 个顶点）两种形状。
页面顶部有提示：**新增的禁飞区会立即参与下一次路径规划**，这是演示"动态空域管制"最直观的方式。

## 5. 几个值得说明的实现点

### 5.1 地图：中国地图 + 真实城市路网的两级结构

底图由两层叠加而成，各司其职：

| 层 | 实现 | 内容 | 生效范围 |
| --- | --- | --- | --- |
| **中国地图** | `map/ChinaBaseLayer.ts`（`L.geoJSON`） | 真实省级边界、海面、经纬网、全国省会与重点城市标注（分级显隐） | 全程（z 3–17） |
| **真实城市路网** | `map/SimTileLayer.ts`（自研 `L.GridLayer`） | 环形放射骨架、三级不规则路网、街区肌理、蜿蜒水系、绿地、机场跑道 | z ≥ 9 叠加，逐级加密 |

**为什么需要中国地图**：只画程序化的路网，用户会问"这是哪儿"——
没有省级边界与城市名，就没有地理参照。569KB 的省级 GeoJSON 给出了方位锚点。

**为什么还需要城市路网**：省级边界在 z ≥ 9 的城市尺度上就是一块平色，
作业区会看起来"空无一物"。叠加一层程序化路网既补上了尺度感，又完全离线。

**为什么不用天地图/高德/OSM 做底图**：
1. 在线瓦片在内网、断网、或服务不可达时就是一片空白，用户看到的是"没有地图"；
2. 商用需要授权，教学项目不宜埋这个坑；
3. 仿真沙盘只需要方位与距离感，不需要商铺门牌号。

#### 路网怎么做到"像真的"

早期版本把路网画成了**规则经纬网格**——每一格一样大、每条路一样直，
一眼就是"草稿纸"。现在按真实城市的形态生成：

1. **环形放射骨架**：3 条环线 + 13 条放射主干道从市中心辐射，
   带轻微椭圆、摆动与偏转——这是最容易被认出"这是一座城市"的结构。
   环线与部分放射线用暖黄色（真实地图上高速/高架的惯例配色）区分层级。
2. **蜿蜒水系**：黄浦江（宽 620 m，南→北穿城后在陆家嘴东折）+ 苏州河 +
   两条运河 + 湖泊，按真实尺度线宽绘制；**道路遇到水面会断开**（相当于桥之外不能过河）。
3. **三级嵌套路网 + 街区**：主干（≈556 m）/ 次干（≈278 m）/ 支路（≈139 m）
   **全部由同一个基准格 `LATTICE_STEP` 派生**，因此粗细路网互相咬合——
   不会出现"大路从街区中间横穿"的假象。每条格线按哈希抖动位置（±55% 格距）、
   并按 12% 概率"缺一条"，于是街区大小天然参差、有断头路，这才是城市肌理。
4. **渐进细节**：z ≥ 9 只画骨架，z ≥ 11 加主干网格，z ≥ 13 加次干道与街区，z ≥ 15 加支路。

#### 四个实现要点

- **图层压叠用自建 pane**：中国地图在 `chinaBase`(z=180)，路网瓦片在 `tilePane`(200)，
  空域/航路在 `overlayPane`(400)，无人机在 `markerPane`(600)。
  Leaflet 默认把矢量放 overlayPane，如果直接把 GeoJSON 画进去，路网瓦片反而会被盖住；
- **底图关掉交互**：35 个省级多边形、上万个顶点若逐个参与 hit-test，
  拖动会明显变卡，所以中国地图全部 `interactive: false`；
- **一切随机量都来自稳定哈希**（不是 `Math.random()`）：瓦片会被反复创建，
  随机数会让同一块地皮每次重绘都变色，看起来像画面在闪；
  同理，街区色块的格线与路网格线必须共用同一个哈希函数，否则色块会横跨道路。
- **道路用「描边 + 路面」两笔**：底图陆地色接近纯白，纯白路面在白底上根本看不见，
  所以先画稍宽的深色描边、再画本色路面，路才立得住。

#### 地名标签：分级显隐，而不是"全塞进去"

地图上真实存在的约束是**可用的屏幕面积**。34 个省级名称 + 几十个城市名如果常驻显示，
缩到全国视野就是一团黑块（用户反馈"省份的字体都会占到一块"）。所以两层标签都按缩放分档：

| 缩放 | 城市标注（`ChinaBaseLayer`） | 行政区划名称（`AdminBoundaryLayer`） |
| --- | --- | --- |
| z < 4 | 不显示 | 不显示 |
| 4 ≤ z < 7 | 34 个省会 / 直辖市 / 港澳台（`rank 0`，含福州、台北） | 只标**短名**的省级区划（北京、上海、福建…） |
| z ≥ 7 | 追加 23 个计划单列市与重要地级市（`rank 1`，含深圳、厦门、台中、高雄） | 下钻视图：标市 / 区县名 |

低缩放时让长名（内蒙古自治区、新疆维吾尔自治区）先让位，放大后再补回来 —— 这不是"少标几个"，
而是把有限面积优先给能读清的短名。

#### 放大到哪，就自动看到哪一级的边界

手动"点省面才下钻"不符合地图的默认预期：用户把地图放大到福建，想看的就是福州和它的区县。
所以在 `zoomend` 与 `moveend` 里跟一次视野：

- **阈值取 z6 而不是 z7**：全国默认视野停在 z4，用户"放大"两格才到 z6；定在 z7 时实测滚 4 格
  仍停在 z6（Leaflet 的缩放动画会吃掉相邻两次滚轮中的一次），屏幕上什么都不出来。
  z6 的可见宽度约 500km，已经是一座省的范围；
- **先看视野中心落在哪个省**（射线法 `pointInFeature`），中心在海上/湖上、或视野里没有省界时，
  退化为"与视野重叠面积占视野比例最大的省"（要求 ≥ 0.35）—— 沿海城市（上海、深圳、厦门、台北）
  放大后中心常常正在水面上，只看中心点会得出"这里不属于任何省"；
- **`moveend` 也要跟**：拖动只触发 `moveend` 而不触发 `zoomend`，而用户的动作几乎都是
  "先放大、再把地图拖到我要看的城市"。只在 `zoomend` 判断的话，他拖到福州之后什么都不会发生；
  只有**自动**下钻会跟随视野换省，用户主动选的省份不被改动；
- **缩回全国自动退出**（z < 6），并把"已回全国"同步回父组件（下拉框与面包屑都在父组件里，
  只清图层不通知就会出现"图上已是全国、面板还写着甘肃省 + 返回全国"的错位）；
- **加载与失败都要说话**：下级边界是按 adcode 在线拉的，首次要一秒多，港澳台等区划没有
  `_full.json`。所以拉取期间面板显示"正在加载「×省」的市/区县边界…"，失败则显示原因 ——
  静默失败只会让用户得出"放大也看不到市区县"的结论，而这恰恰是他最想看的东西。
- 拉取失败**不清空**已有内容、不弹错打断操作。

**中国地图数据怎么来**：由 `scripts/fetch-china-geo.mjs` 下载到 `public/geo/china.json`，
**不提交进仓库**（体积 569KB，且第三方地理数据的商用授权需要使用者自行确认）。
`pnpm install` 之后会自动尝试执行一次（`postinstall`），也可以手动：

```bash
pnpm run fetch:geo        # 或 node scripts/fetch-china-geo.mjs
```

没跑这个脚本时前端不会崩：底图退化为纯程序化地图（此时路网层会提前到全程叠加），
HUD 上会给出黄色提示与上面这条命令。

#### 平面 / 立体双视图（`map/Scene3DView.vue`）

平面地图把"高度"压扁了：它只会告诉你飞机在哪，不会告诉你
"这架飞机正从 180m 的写字楼顶上飞过"。所以态势地图提供**视图切换**（HUD 第一行
【平面 | 立体】），立体视图用 Three.js 把同一批数据立起来：

| 元素 | 立体视图里怎么画 | 说明 |
| --- | --- | --- |
| 空域 | 挤出成体块：**建筑障碍**是实心灰块（可绕可越），禁飞/限飞是半透明红/橙体块 | 高度取自 `maxAltitudeM`，能直接看出"从上方飞过"是否可行 |
| 无人机 | 每架一个真正的四旋翼模型，悬在各自真实高度上 | 几何体与 3D 建模弹窗共用 `drone/droneGeometry.ts` |
| 高度 | 每架下方有**地面光环**（状态色）与**竖直投影线**（地面 → 机身） | 没有这两个参照，观众无法从俯视图判断谁高谁低 |
| 航路 / 订单 | 航路抬到巡航高度画折线；取货点是蓝色矮台、目的地是按状态着色的光柱 | 与地面拉开层次，能看出"航线从楼顶上跨过去" |

三个必须解释的换算（都写在界面上，不做隐性欺骗）：

1. **水平 1 场景单位 = 1 米**，经纬度按等距圆柱投影折算成局部米制平面；
2. **垂直方向放大 3 倍**（`VERTICAL_EXAGGERATION`）。一个 4km 宽的城市视野里，
   真实 120m 的飞行高度只占画面 3%，楼与飞机全糊在地上；楼高与高度**同比例**放大后，
   "楼顶之上"的层次关系才看得出来；
3. **无人机按示意尺寸绘制**（`DRONE_SIZE_M`）。真机翼展在这个尺度下不足一个像素 ——
   与平面地图使用固定大小图标是同一个取舍。

两个关键实现约束：

- **插值只算一次**。位置/姿态的指数平滑与姿态解算都在 `DroneMap.vue` 的动画循环里完成，
  立体视图通过 `updateFrames()` 被动接收 `{lat, lon, altitudeM, headingDeg, rotorLevel, status}`。
  两边各插一次值的话，切视图时同一架飞机会出现在两个位置上。
  注意交付的数组是**复用**的，立体视图内部必须存副本，否则拿到的是空数组。
- **一次只立一座城**。栅格场景是按真实米制搭的，把全国视野（上千公里）立起来只会是一块空地。
  所以切换时若视野跨度 > 15km（`SCENE3D_MAX_SPAN_M`），自动收敛到机队最密集的作业区
  （与低缩放下的"作业区"汇总标记用同一套聚类，认知一致），场景跨度再收敛到 12km 以内。
  相机 `far` / 雾效 / 滚轮范围都跟着跨度同步（`syncCameraScale`），否则要么远处被裁掉、
  要么滚轮能缩到场景外。

切回平面时必须 `map.invalidateSize()`：Leaflet 容器刚从 `display:none` 恢复，
不重新量尺寸就会出现灰边或图层错位。两个视图都用 `v-show` 而不是 `v-if` ——
销毁重建要重载省级 GeoJSON 与瓦片，来回切两次就能感到明显卡顿；
立体视图另以 `active` 开关停掉渲染循环，切回平面后不白烧 GPU。

相机预设给了四个：**斜视**（约 40° 俯角，默认，楼群层次最清楚）、**俯视**、
**贴近**（低角度近距离，看清单架飞机与它脚下的楼顶）、**跟随选中**
（把轨道中心缓慢贴到选中的那架飞机上，它飞出画面也能跟上）；另有「聚焦机队」
把相机收拢到当前场景里的飞机（保持观察方向不变，不会突然天旋地转）。

#### 立体视图怎么"动起来"，以及地势海拔

第一版做完立体视图后，用户的反馈很直接：**"不会移动，只能看到一小片区域，而且全国地势海拔不一样"**。
三个问题分别对应三处设计：

| 问题 | 做法 | 为什么这么做 |
| --- | --- | --- |
| 看不到别的区域 | 视角中心漂出 0.35 个跨度（`RECENTER_DRIFT_RATIO`）就**换原点**：内容与相机按同一量平移，屏幕画面保持连续，`rebuildStatic()` 按新原点重算空域/航路/订单的坐标 | 只有换原点，场景才能像平面地图那样"无限延伸"；不平移相机画面就会原地跳一下 |
| 不知道视角有没有动 | **WASD 长按连续飞行**（按住 WASD 移动，Q/E 改范围）+ **四方向平移按钮**（每按一次 0.9 个跨度）+ **范围增减按钮**，HUD 常驻显示**视野中心经纬度** | 立体视图里没有任何手势提示，用户不会去猜"右键能平移、滚轮能缩放"；而"画面看起来差不多"时，一个会变的坐标读数是唯一能自证的依据 |
| 全国地势海拔不同 | 按城市给**基准海拔**（`SITE_ELEVATIONS`：上海 4m / 成都 500m / 太原 780m / 拉萨 3650m……），世界根节点整体抬升 | 真实 DEM 体积大、获取麻烦；城市级基准海拔足以表达"山西的地面架在高处"，不必铺真实高程网格 |

关键实现细节：

- **世界根节点** `worldGroup`：所有可见内容都挂在它下面，抬海拔只改这一个节点的 y。
  否则每加一种元素（空域、建筑、航路、无人机、地面网格……）都要记得单独加海拔偏移，漏一处就穿模。
- **相机也要跟着抬**：换个高海拔城市（上海 → 成都）时，若只抬地面，相机就会"埋到地下"。
  所以 `applyElevation()` 会把 `camera.position.y` 与 `controls.target.y` 同步平移同样的量。
- **换原点后要通知父组件**：左上角的城市名是父组件算的，不通知就会出现
  "城市名还写着上海、下面的海拔已经变成成都"的矛盾（这是实测抓到的 bug）。
  所以立体场景 emit `recenter`，由 `DroneMap` 用 `cityNameOf()` 重算城市名。
- **相机量级随跨度同步**（`syncCameraScale`）：`far`、雾效、滚轮范围都与跨度绑定，
  否则要么远处被裁掉、要么滚轮能缩到场景外。
- **键盘是"按住"，不是"按一下走一步"**：keydown 只登记方向，位移由渲染循环按时间逐帧累加
  （`KEY_FLY_SPAN_PER_SEC` = 0.35 跨度/秒）。若按按钮那样的步长处理每次 keydown，
  操作系统的按键自动重复会让长按一秒窜出去十几个视野。两条边界也要守住：只在立体视图激活时生效
  （`props.active`），焦点在 input/textarea/select/contenteditable 上时**不抢键**；窗口失焦清空按住的键。
- **HUD 的视野中心读数取"相机当前对准的地面点"**，而不是换原点的位置：换原点要等漂移超过 0.35 个跨度，
  读数若绑在原点上的话，按住 WASD 的头一秒读数纹丝不动，用户会以为键盘没生效。

### 5.2 表单里的坐标一律在地图上点选（`map/PointPickerMap.vue`）

让运营手填"纬度 31.230400、经度 121.473700"是不现实的：差一位小数就是几公里偏差，
而且没人知道那串数字落在城市的哪一边。所以两个表单都改成**地图点选**：

| 表单 | 原来 | 现在 |
| --- | --- | --- |
| 无人机注册（`/drones`）· 起降点 | 两个数字输入框 | 点击地图设定 + 拖动标记微调，数字框保留用于精确到小数点后 6 位 |
| 新建订单（`/orders`）· 取货点 / 送货点 | 四个数字输入框 | 一张地图 + 「正在拾取」取货点/送货点切换，另一个点画成参照圆点 |

三个设计决定：

- **与空域拾取器分开**。`AirspacePickerMap` 是"画范围"的编辑器（圆心 + 半径 + 多边形顶点 +
  撤销重画）；本组件只做"选一个点"，所以没有草稿图形、没有手柄，API 只有 `lat` / `lon` 两个双向绑定。
- **参照点不接收点击**。地图点击在这里的语义是"把当前点放到这儿"；如果参照标记也抢点击，
  用户点一下想切换、结果把坐标改掉了 —— 这类"点哪改哪"的歧义在表单里极易出错。
  切换当前点交给地图上方的选择器。
- **空域当参照层画出来**。起降点落在禁飞区里等于"这架机永远飞不起来"，收货点在楼群里则要多绕几公里 ——
  这些区域在点选时就应该看得见，而不是事后从调度失败原因里反推。空域拉取失败静默降级。

订单表单里"当前拾取哪个点"用一对**可写计算属性**接地图的 `v-model`：

```
activeLat = computed({
  get: () => activePointKey === 'pickup' ? form.pickupLat : form.dropoffLat,
  set: (v) => { if (v === null) return; if (activePointKey === 'pickup') form.pickupLat = v; else form.dropoffLat = v },
})
```

比写两套地图、或在组件里塞 `if/else` 都干净；两个点的坐标各自独立，互不覆盖。

### 5.3 无人机：四旋翼模型，而不是圆点

**外形随型号变化**（`components/drone/droneGeometry.ts`）：三种机型不再共用一套模型 ——
轻量机四旋翼（小机身细机臂）、中型机六旋翼（六边形机身 + 圆顶）、重载机八旋翼
（厚方舱 + 外露电池包 + 宽起落架 + 双货舱），几何体按 `modelCode` 参数化，机队页的
3D 建模抽屉与态势地图的立体视图共用同一份。遥测帧为此新增 `modelCode` 字段
（`DashboardDtos.DroneFrame`）：不加这个字段，前端根本不知道每架机该长什么样。

`components/map/droneIcon.ts` 用内联 SVG 画出**俯视四旋翼**（机身 + 四条机臂 + 四个旋翼 + 云台），
并让每个部件承载状态信息：

| 视觉元素 | 表达的信息 |
| --- | --- |
| 整体按 `heading` 偏航（机头在 SVG 里朝上） | 飞行方向 —— "在飞"最直接的证据 |
| 四个旋翼两叶薄片持续旋转，**转速随水平速度变化**（悬停 ~0.3s/圈，巡航 ~0.12s/圈） | 处于工作状态，且能看出"在悬停还是在赶路" |
| 机身主色跟随状态 | 空闲绿 / 飞行蓝 / 返航橙 / 维护黄 |
| 低电量红色脉冲圈 | 需要关注（<25% 且非空闲、非充电） |
| 机腹货箱 | 是否载货（有任务且不在返航阶段） |
| **横滚 → 机身沿横向压扁** | 转弯压坡度（协调转弯 `tanφ = v·ω/g`），左转/右转方向与坡度大小都能看出来 |
| **俯仰 → 机身沿纵向压扁** | 爬升抬头 / 下降低头（flight-path angle） |
| 高度 → 图标放大 + 机腹阴影**淡出 / 缩小 / 错开** | 三件事一起做，才像"离地很高" |
| 选中时机身发光 + 航向锥 | 前方意图；锥长随速度变化 |

**姿态是渲染层算出来的，不是后端字段**。服务端只给"在哪、多快、多高"；
前端在插值循环里用**时序变化**反解姿态：垂直速度 → 俯仰、转弯角速度 → 横滚、水平速度 → 旋翼转速。
真实巡航倾角只有 5°~15°，俯视图下压缩不到 5%，肉眼根本看不出来，
所以乘了一个**制图夸张系数 1.35** —— 这与"把道路画得比实际更粗"是同一种取舍。
姿态平滑的时间常数（0.5s）比位置（0.32s）大，转弯结束后机身会自然回正而不是瞬间弹平。

五个必须注意的实现细节（都是会直接导致"图标乱飞/不显示/抖动"的坑）：

- 图标样式必须写在 `styles/global.css`，**不能写组件的 `<style scoped>`** ——
  divIcon 的 HTML 是运行时插入的，不在 scoped 作用域内；
- 旋转与缩放要写在**同一个** `transform` 里，且只能作用在**内层** `.drone-rot` 上 ——
  Leaflet 会给图标根元素写 `translate3d` 做定位，根元素上再写 transform 会打架；
- 旋翼旋转必须配 `transform-box: fill-box`，否则 CSS 旋转以 SVG 视口原点为中心，
  旋翼会直接飞出画面；
- 旋翼转速用 `--rotor-duration` CSS 变量驱动动画时长，但**必须先量化成 7 档再写** ——
  连续微调 `animation-duration` 会让正在跑的动画不断重映射进度，看起来是一顿一顿的；
- 姿态只在**开启插值**时解算：关掉插值时逐帧跳变会算出巨大的瞬时导数，姿态会乱甩。

### 5.4 平滑运动：位置与高度插值

后端 1 秒推一帧，8 倍速下每帧位移 120 米以上。直接 `setLatLng` 会看到"一跳一跳"。
这里用 `requestAnimationFrame` 维护每个目标的**显示位置与显示高度**，
向**服务端最新值**做指数平滑：

```
display += (target - display) × (1 - e^(-dt/τ))      τ = 0.32s
```

航向同样用最短弧插值（`lerpAngle`），从 350° 转到 10° 时不会反向绕一大圈。
高度也一起插值，于是"起飞爬升"看起来是平滑抬升，而不是从 0 直接跳到 80 m。
动画限到约 30fps（数据每秒才更新一次，60fps 没有收益），
超过 80 架自动关闭插值改为按帧更新，保帧率优先。

### 5.5 航迹尾迹

每架无人机保留最近 90 个采样点（相邻点间距 ≥25 米才记一个新点），用**点线**绘制，
与"计划航路"的实线一眼区分。尾迹是"近期轨迹"；完整历史请用遥测 CSV 导出回放。

### 5.6 地图性能：增量更新

地图每秒都在刷新，是前端最容易卡住的地方。三条措施：

1. 空域/航路/尾迹走 `preferCanvas: true` 的 Canvas 渲染，只有无人机用 SVG 图标（几十架无压力）；
2. **按 droneId / taskId 缓存图层对象**，只更新坐标与样式，
   **绝不"清空图层再重建"**（那是最常见的写法，也是卡顿的元凶）；
3. 只在**第一次**拿到数据时 `fitBounds` 自适应视野，之后不再自动移动——
   否则用户刚拖动地图就被拽回去。

另外容器尺寸变化后必须调 `map.invalidateSize()`，否则侧栏折叠时地图会出现灰边。

### 5.7 实时通道：WebSocket 优先，REST 轮询兜底

`store/telemetry.ts` 里是一条完整的降级链：

```
连接 WebSocket
  ├─ 成功 → 服务端主动推 SNAPSHOT 全量快照，之后每秒推 TELEMETRY
  └─ 失败 → 指数退避重连（1s → 2s → 4s → … 上限 15s）
              └─ 连续失败 3 次 → 自动开启 REST 轮询（3 秒一次）并给出黄色横幅提示
```

关键细节：

- WebSocket 地址用 `location.host` 拼，**不写死 `localhost:8080`**。开发时走 Vite 的 `/ws` 代理，
  生产走 Nginx 转发，前端代码零改动；
- 主动关闭前把 `onclose` 置空，否则会触发一次多余的重连（表现为"点一下断开，它自己又连上了"）；
- 冲突消息按 id 去重，事件流与冲突列表各自限长（120 / 50 条），防止长时间运行把内存吃满。

### 5.8 ECharts 按需引入与资源释放

```ts
import * as echarts from 'echarts/core'
import { BarChart, PieChart } from 'echarts/charts'
import { GridComponent, LegendComponent, TooltipComponent } from 'echarts/components'
import { CanvasRenderer } from 'echarts/renderers'
echarts.use([PieChart, BarChart, GridComponent, TooltipComponent, LegendComponent, CanvasRenderer])
```

只注册用到的模块，体积从完整包的 ~1MB 降到几十 KB。同时：

- 用 `ResizeObserver` 监听**容器**（而不是 window）——侧栏折叠时窗口尺寸没变但容器变了；
- `onUnmounted` 里必须 `dispose()`，只清 DOM 会残留实例与监听器。

### 5.9 接口层：统一解包 + 统一报错

后端所有接口都返回 `{ code, message, data, timestamp }`。`api/client.ts` 只在这里解包一次，
页面拿到的就是纯业务数据，不用到处写 `res.data.data`；业务码非 0 或 HTTP 非 2xx 时
自动弹 Ant Design 的 message 并抛出 `ApiError`，页面只需在 `catch` 里收尾 loading。

> ⚠️ 一个容易踩的坑：后端配了 `spring.jackson.default-property-inclusion: non_null`，
> **值为 null 的字段不会出现在 JSON 里**（而不是出现为 null）。
> 所以 `types.ts` 里所有可空字段都写成可选（`?`），模板里一律 `?? '—'` 兜底。

### 5.10 跨域

开发期用 Vite 代理（`/api`、`/ws` → 8080），浏览器视角是同源，**不会触发 CORS**。
后端另外配了 `WebConfig` 放行 `localhost:5173` / `4173`，用于 `pnpm preview` 或直接 fetch 调试。
生产部署用 Nginx 转发，同样不需要 CORS。

## 6. 生产部署

```bash
pnpm build          # 产出 frontend/dist
```

Nginx 参考配置（注意两个易错点：SPA 回落 与 WebSocket 升级头）：

```nginx
server {
  listen 80;
  root /usr/share/nginx/html;            # 指向 dist

  location / {
    try_files $uri $uri/ /index.html;    # history 路由必须回落，否则刷新 /orders 会 404
  }
  location /api/ {
    proxy_pass http://sky-dispatch-backend:8080;
  }
  location /ws/ {
    proxy_pass http://sky-dispatch-backend:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;      # 缺这两行 WebSocket 握手会 400
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 3600s;                     # 长连接别被 60s 默认超时掐断
  }
}
```

## 7. 已知限制

| 限制 | 说明 | 演进 |
| --- | --- | --- |
| 无登录与权限 | 假设内网使用；所有操作对所有人开放 | 接 SSO / JWT，按角色控制派单与空域编辑 |
| 地图是程序化沙盘 | 路网形态真实（环形放射 / 三级嵌套 / 水系），但**不是真实街道**，看不到真实路名与建筑（这是**有意为之**：沙盘只需方位与距离感） | 需要真实底图时接入内网瓦片服务，`DroneMap.vue` 里替换图层即可 |
| 路网骨架是"手绘参数" | 环线与放射主干道由固定参数生成（与上海大致神似，不保证与真实路网重合）；水系为示意折线 | 想更真实可换成真实矢量数据（开源 OSM 导出）离线切片，接口不变 |
| 无人机图标是 SVG | 几十架流畅；上百架时 DOM 图标会成为瓶颈（已自动降级为不插值） | 换 WebGL 渲染（如 deck.gl / three.js）做真正的三维机队 |
| 单页全量注册 Ant Design Vue | 首屏体积偏大（内部后台可接受） | 换 `unplugin-vue-components` 按需引入 |
| 空域编辑只有增删 | 不支持修改已有区域，也不支持在地图上拖拽绘制 | 加编辑表单 + Leaflet.Draw |
| 无回放播放器 | 只能看任务的事件时间线与导出 CSV 自己分析 | 用遥测数据做时间轴回放（读取 `/reports/tasks/{id}/telemetry.csv` 或按 `sim_time_s` 拉历史） |
| 表格无虚拟滚动 | 任务/订单超过几千条时滚动会变涩 | 换 `a-table` 的 `virtual` 或分页收紧 |
| 状态无持久化 | 刷新页面靠 SNAPSHOT 重建，切换页面不丢（store 是单例） | 若要多标签页同步，引入 BroadcastChannel |
