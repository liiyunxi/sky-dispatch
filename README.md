# sky-dispatch · 低空经济无人机配送调度仿真平台

> **纯软件仿真，不涉及真实硬件。** 通过模拟订单、无人机与空域，实现自动调度、路径规划、
> 冲突检测、离散事件仿真与实时监控 —— 一套可以完整演示、也适合初学者逐层读懂的低空物流调度系统。

```
订单进来  →  自动选机  →  绕开禁飞区规划航路  →  逐拍仿真飞行  →  冲突告警  →  送达返航  →  导出报告
```

## 1. 核心特性

| 模块 | 能力 |
| --- | --- |
| **订单管理** | 创建/查询/取消，优先级（LOW→URGENT）、期望送达时间、完整状态机 |
| **无人机管理** | 机型能力字典（载重/速度/续航/能耗/悬停功率）、单机台账与实时状态、乐观锁 |
| **调度分配** | 三种可插拔策略（最近可用 / 电量优先 / 负载均衡）+ 硬条件筛选 + **可达性分析（不只看电量，还会算经停补能）** + **决策可解释** |
| **路径规划** | Python A*：栅格搜索、障碍膨胀、高度区间判定、**两级平滑（视线法压拐点 + 转弯半径圆角化）**、无解可识别 |
| **自主补能** | 长航程任务的电量不足以飞完剩余航程时，**无人机自己判断**并改航到就近充电站，落桩补能、充满续飞（`BatteryRelayService`）；补能网络**全国通用**（35 个省会/直辖市/港澳台各 1 座 + 四个演示城市加密，共 40 座），站点位置决定运力半径 |
| **冲突检测** | 机-机（轨迹外推）、机-区（含外推侵入）、低电量，分级告警 + 指纹去重 + 决策可解释 |
| **演示持续运营闭环** | `dev` profile 默认开启：① 待派/在飞订单不足时，<b>以空闲且电量充足的飞机为运力锚点</b>自动补充其必然能送达的近距订单（送完不会整体静止）；② 飞机回站自动补能、低电量保护后充至阈值自动复飞（机队不趴窝）。两者均可通过 `sky.simulation.demo-replenish-enabled` / `demo-recharge-enabled` 关闭，`postgres`（生产）默认关闭——真实订单只来自客户、充电由换电调度负责 |
| **仿真引擎** | 离散时间步进、逐拍位置推进、**飞行剖面（起飞加速→爬升→巡航→下降→减速降落）**、载重感知电量消耗、强制返航保护、状态机驱动（无人机状态随任务同步为飞行中/返航中） |
| **冲突检测与自动避让** | **Java 本地时空预测（无需 Python）**：对未来 60 秒按 4 秒采样，检测机-机水平间隔 <60m 且同高度层、机-区（圆/多边形 + 高度层）冲突；预测到冲突后**自动切换航线**——空域冲突在穿越区间的"进入前/中点/离开后"插入逐级加大（200m~3.2km）的整段侧向绕飞，机-机冲突插入侧向狗腿；候选航路用与检测相同的预测器对**所有**在飞飞机和全部空域全量校验（取最短可行方案，避免"为躲 A 撞上 B"的二次碰撞），并校验剩余电量足够返航；无法避让时保留 CRITICAL 告警交人工处置 |
| **实时看板** | Vue3 + Ant Design Vue 运营控制台：态势地图、KPI 卡片、机队表格、冲突/事件面板（改航记录含"系统已自动切换航线避让"）；原生 WebSocket 推送 + REST 兜底 + 自动重连 |
| **回放与报告** | 事件时间线、遥测轨迹、CSV 导出（UTF-8 BOM，Excel 直接打开不乱码） |

**一键可跑**：`dev` profile 用 H2 内存库，**不需要安装任何数据库**，启动即自动灌入演示数据并开始仿真。
前端是标准的 Vite 工程，`pnpm install && pnpm dev` 即可打开运营控制台。

## 2. 架构与技术栈

```
浏览器（Vue3 + Ant Design Vue 控制台）
        │  REST（拉）                │  WebSocket（推）
        ▼                            ▼
┌──────────────────────────────────────────────────────────┐
│  Java 21 · Spring Boot 3.4 · :8080                       │
│  业务 · 调度 · 仿真引擎 · 事务 · 状态机 · 实时推送          │
└───────┬──────────────────────────────────────┬───────────┘
        │ JDBC                                 │ REST（可降级）
        ▼                                      ▼
┌───────────────────────┐        ┌────────────────────────────┐
│ PostgreSQL / PostGIS  │        │ Python 3.13 · FastAPI :8000 │
│ 12 张表 + 2 个视图     │        │ A* 路径规划 · 冲突检测       │
└───────────────────────┘        └────────────────────────────┘
```

| 层 | 技术 | 选型理由 |
| --- | --- | --- |
| 后端 | Java 21 + Spring Boot 3.4 | 事务、状态机、定时步进、生态成熟 |
| 算法 | Python 3.13 + FastAPI + uv | 算法迭代快、可接科学计算生态、无状态易替换 |
| 数据库 | PostgreSQL 14+ / PostGIS（可选） | 空间查询与 JSON 能力；核心表不依赖 PostGIS，纯 PG 也能跑 |
| 前端 | **Vue 3.5 + Ant Design Vue 4 + TypeScript + Vite** | 后台管理组件最全（表格/表单/抽屉/时间线/统计卡）且中文本地化开箱可用；Vite 冷启动秒级 |
| 可视化 | Leaflet（平面地图）+ **Three.js（立体视图与无人机 3D 建模）** + ECharts（图表，按需引入） | 轻量、无 token、按需引入后体积可控；Three.js 直接产出可交互的三维场景，无需外部模型文件 |
| 通信 | REST + 原生 WebSocket | REST 保证准确，WebSocket 保证流畅；开发期用 Vite 代理规避跨域 |

详细架构见 [`docs/01-architecture.md`](docs/01-architecture.md)，前端细节见 [`docs/07-frontend.md`](docs/07-frontend.md)。

## 3. 快速开始（5 分钟）

### 前置要求

| 工具 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 17+（本项目按 21 编译） | `java -version` |
| Maven | 3.8+ | `mvn -v` |
| uv | 最新 | `uv --version`；也可用 `python -m venv` + `pip` 替代 |
| Node.js | 20+ | `node -v`（前端需要） |
| pnpm | 9+ | `pnpm -v`；也可用 npm |
| PostgreSQL | 14+ | **可选**，只有 `postgres` profile 需要 |
| Docker | 最新 | **可选**，用于一键起 PostGIS |

### 启动（三个终端）

> **最快方式（Windows）**：直接运行项目根目录的一键启动脚本，它会固定端口、
> 分窗拉起算法服务（8000）、后端（8080）与前端（5173）、等待就绪并自动打开浏览器，
> 从根上避免"只起了前端、每个接口都报 500"，也避免"后端开了 A* 却没起算法服务"：
>
> ```powershell
> pwsh -File .\start-dev.ps1                 # 算法服务 + 后端 + 前端（dev 默认启用 A* 路径规划）
> pwsh -File .\start-dev.ps1 -NoAlgorithm    # 只起前后端；后端需加 -Dsky.algorithm.enabled=false 走直线降级
> pwsh -File .\start-dev.ps1 -NoBrowser      # 启动后不自动打开浏览器
> ```
>
> 脚本会把 `UV_CACHE_DIR` 指到项目内的 `.build\uv-cache`（部分受限环境无法写全局 uv 缓存，
> 不改会启动即失败）。想分别控制三个服务，或在非 Windows 环境启动，再用下面的手动方式。

```bash
# ── 终端 1：算法服务（8000）─────────────────────────────
cd algorithm-service
uv sync
uv run uvicorn app.main:app --port 8000
#   验证：curl http://localhost:8000/health

# ── 终端 2：Java 后端（8080，H2 内存库，自动灌演示数据）──
cd backend
mvn spring-boot:run
#   验证：curl http://localhost:8080/actuator/health

# ── 终端 3：前端控制台（5173）────────────────────────────
cd frontend
pnpm install
pnpm dev
#   打开：http://localhost:5173
```

启动后几十秒内，仿真引擎就会自动把订单派出去，无人机开始飞行，控制台上能看到飞机在地图上移动。

### 跑一遍完整链路

```bash
# 浏览器打开运营控制台，看地图与指标
start http://localhost:5173

# 或者用脚本把「下单 → 派单 → 步进 → 导出」整个跑一遍（纯后端验证）
pwsh -File tools/smoke-test.ps1
```

前端开发服务器通过 Vite 代理把 `/api` 与 `/ws` 转发到 8080，**浏览器视角是同源，不会触发跨域**。
也可以选择只跑后端 + 零构建调试页 `tools/dashboard.html`（不需要 Node 环境）。

### 用 Swagger 手工试

- Swagger UI：<http://localhost:8080/swagger-ui.html>
- H2 控制台：<http://localhost:8080/h2-console>（JDBC URL `jdbc:h2:mem:skydispatch`，用户名 `sa`，空密码）

### 连真实 PostgreSQL / PostGIS

```bash
docker compose up -d          # 起 PostGIS（见 docker-compose.yml）

cd backend
mvn spring-boot:run -Dspring-boot.run.profiles=postgres
#   Flyway 自动执行 db/migration 下的 V1、V2
```

### 环境变量（可选）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `SKY_PROFILE` | `dev` | 切换 `dev` / `postgres` |
| `SKY_ALGO_URL` | `http://localhost:8000` | 算法服务地址 |
| `SKY_ALGO_ENABLED` | `false`（dev profile 为 `true`） | 是否启用算法服务；关闭后路径规划降级为直线航路（不避让禁飞区）。dev 默认开启，可用 `-Dsky.algorithm.enabled=false` 覆盖 |
| `SKY_RELAY_CHARGING` | `false`（dev profile 为 `true`） | 是否允许无人机**自主改航到充电站补能**；关闭后电量不足直接强制返航/中止 |
| `VITE_BACKEND_URL` | `http://127.0.0.1:8080` | **前端** Vite 代理目标；后端不在 8080 时用它指过去 |
| `DB_HOST` / `DB_PORT` / `DB_NAME` | `localhost` / `5432` / `sky_dispatch` | 数据库连接 |
| `DB_USER` / `DB_PASSWORD` | `sky` / `sky123456` | 数据库账号 |

### WebSocket

`ws://localhost:8080/ws/telemetry` —— 原生 WebSocket，纯文本 JSON 帧：

```json
{ "type": "TELEMETRY", "ts": "...", "payload": { "simTimeS": 13.0, "drones": [ ... ] } }
```

| type | 时机 |
| --- | --- |
| `SNAPSHOT` | 连接建立时立即推一次全量快照 |
| `TELEMETRY` | 每个仿真 tick 推位置与电量 |
| `EVENT` | 订单/任务状态变化（事务提交后） |
| `CONFLICT` | 新发现冲突 |
| `KPI` | 每 5 拍推一次汇总指标 |

| POST | `/api/v1/conflict/check` | 冲突检测 |

## 6. 前端控制台

Vue 3 + **Ant Design Vue 4** + TypeScript + Vite，5 个页面：

### 顶部控制条（这一版重点改的地方）

早期版本有个真 bug：**「停止」按钮无效** —— 引擎每拍发现没有运行就新建一个，
点停止后 1 秒又自己跑起来。同时「立即批量派单」看起来没反应，
因为后台每 10 秒也在自动派单，而待派的又恰好是飞不到的订单。

现在把"跑仿真"和"派单"拆成两个独立开关：

| 控件 | 作用 |
| --- | --- |
| **暂停 / 继续仿真** | 暂停后定时推进**真的停下**（不会再自己复活），但「步进一拍」仍可用，可以逐拍观察状态机 |
| **自动派单开关** | 关闭后订单只排队等待，派给谁、什么时候派完全由你决定 —— 这样「立即批量派单」才是一个能被验证的动作 |
| **步进一拍** | 不依赖定时器手工推进一个时间片（暂停状态下同样可用） |
| **新建运行** | 结束当前运行、计时与拍数从 0 重新开始（「继续」则从暂停处接着跑） |
| **立即批量派单** | 按钮上显示待派单数，为 0 时禁用；点完弹出**逐单结果**：派给了谁，或者为什么没派成 |

顶部还常驻：**实时通道健康度**（WebSocket 已连接 / 重连中 / 已降级为轮询）、仿真运行状态与拍数、
**算法服务是否在线**（离线时首页顶部弹红色横幅，因为此时派单必定 503）。

三个实现细节值得单独提：

- **地图是"中国地图 + 真实城市路网"两级结构，不依赖任何在线底图**。
  中国地图用省级 GeoJSON 画真实边界、海面、经纬网与城市标注；
  放大到 z ≥ 9 再叠加程序化生成的**环形放射骨架 + 三级嵌套路网 + 蜿蜒水系 + 街区肌理 + 机场跑道**。
  这样既有"我在看中国"的方位感，又有作业区的尺度感，而且内网断网都能用 ——
  在线瓦片一旦加载不出来，用户看到的就是"没有地图，只有几个孤零零的点"。
  唯一的例外是备用调试页 `tools/dashboard.html`，它仍用 Leaflet CDN。
- **行政区划可下钻：分省着色 + 省→市→区/县高亮**。地图右上角「行政区划」面板支持：
  ① **单色 / 分省着色**一键切换（分省按 adcode 稳定配色，相邻省份色差大）；
  ② **下拉选省或直接点省面**，按需在线加载该省下的市 / 区县边界（阿里云 DataV.GeoAtlas，按 adcode 绑定、内存缓存），
  其余省份自动淡化、视野缩放至该省；普通省份先看到地级市，**点地级市继续下钻到区/县**，直辖市（京沪津渝）直接到区；
  面包屑可逐级「返回省份 / 全国」。省级边界仍走本地 `public/geo/china.json`（离线可用），
  市/县边界需联网；免费公开数据目前到**区/县级**，乡镇/街道级需另接天地图或商业数据源。
  ③ **名称常驻显示**：省名、市名、区县名直接标注在地图上（不需要鼠标悬停），
  面板里可一键开关；标签锚点优先取 GeoJSON 的 `properties.center`，缺失时取"包围盒面积最大的环"的
  盒心，避免群岛型行政区（舟山、三沙）的标签飘到海上。
- **地图支持全屏**：HUD 里一键把地图铺满整屏（Fullscreen API 作用在地图容器上，只放大地图本身），
  ESC 或再次点击退出；全屏切换后自动 `invalidateSize`，不会出现灰边或图层错位。平面与立体视图都适用。
- **态势地图可以在平面/立体之间切换**：平面看"在哪、往哪飞"，立体看"飞在多高、底下有没有楼"。
  立体视图（Three.js）把空域挤出成体块（**建筑障碍**是实心灰块、禁飞/限飞是半透明红橙体块）、
  把无人机按真实巡航高度悬停、每架下方配一个状态色地面光环与一条竖直投影线（否则俯视时分不清谁高谁低），
  航路抬到巡航高度画折线。相机给了斜视/俯视/贴近/跟随选中四个预设。两个必须说明的换算：
  **垂直方向放大 3×**（不然 120m 的飞行高度在 4km 视野里只占 3%，楼和飞机全糊在地上）、
  **无人机按示意尺寸绘制**（真机翼展不足一个像素）——都标在界面上，不做隐性欺骗。
  插值只在平面视图的动画循环里算一次，立体视图被动接收位姿，所以**切视图不会出现位置对不上**；
  切到立体时若视野还在全国尺度，会自动收敛到机队最密集的作业区（一次只立一座城）。
- **远程配送有充电站，无人机自己判断要不要补能**：机巢只在起点，所以"往返续航不够"的长单
  以前会被派单硬条件直接判死（演示数据里那单 10.5km 的虹桥→中山公园就是，26 架机全被淘汰）。
  现在补能网络是**全国通用**的：按省会清单在 35 个省/自治区/直辖市/港澳台各布 1 座，
  再在四个演示城市的进出走廊上各加密 2 座，共 40 座（`charging_station` 表 + `DemoDataSeeder`）——
  覆盖到哪，运力半径就到哪，不该按城市切分。飞行中每一拍检查
  "剩余航程能耗 > 可用电量 × 1.15"就**自己改航到最近且这点电确实飞得到的站**，
  落桩充到 90% 再续飞未完成的那一段（任务状态 `CHARGING`、飞机状态 `CHARGING`）。
  两个关键约束：去补能的航路终点是充电站，**抵达时必须拦下"送达"逻辑**（否则订单会被提前标成已送达、
  货其实还在机上）；补能期间**不做电量兜底**，否则"自己判断该补能"会被低电量保护提前掐断。
  实测日志：`无人机 UAV-002 自主判断电量不足以飞完剩余航程（约需 692Wh，可用 601Wh），已改航至「虹桥枢纽补能站」` →
  充到 90% → 恢复配送 → 送达 → 返航途中又自主补了一次能 → 订单闭环。
  生产默认关闭（`sky.dispatch.relay-charging-enabled`）：真机自主改航要过适航与空管评估。
- **"能不能送到"不再只看电量**：有补能网络之后，"电量不够"不等于"飞不到"。派单前
  `ReachabilityService` 会把任务建成一张图（起点 → 取货点 → 送货点 → 机巢，外加跳得到的充电站），
  在最多 3 次补能的预算内搜索"补能次数最少"的可行方案，输出**经停几站、经停哪些站、每段耗多少电、
  最紧一段还剩多少余量**。结论直接写进决策明细（`直飞可达：…` / `需经停 2 次补能（…）` /
  `续航不可达：卡在载货段，差 405Wh`），订单页的候选表用绿色「直飞可达」/ 橙色「经停 N 站」区分，
  并统计"直飞 X 架 / 需补能 Y 架"。补能后的可用电量按 `90% - 25% = 65%` 计，与飞行中自主补能同一口径。
- **立体视图不再是"一块死板子"**：支持**按住 WASD 连续飞行**（Q/E 改范围），并配**四方向平移**
  与**范围增减**按钮 —— 立体视图里没有任何手势提示，用户不会去猜"右键能平移、滚轮能缩放"，
  所以把能力摆到明面上；视角中心漂出去超过 0.35 个跨度就换原点、把新区域的空域/楼群/航线加载进来，
  场景可以一直延伸。键盘走"按住"语义而非"按一下走一步"：若按按钮那样的步长处理每次 keydown，
  操作系统的按键自动重复会让长按一秒窜出去十几个视野；同时只在立体视图激活时生效，
  焦点在输入框上时不抢键。
  同时按城市给出**基准海拔**：上海 4m、成都 500m、太原 780m（真实 DEM 体积大、获取麻烦，
  城市级基准海拔足以表达"山西的地面架在高处"），地面、空域体块与无人机整体抬到该海拔上，
  HUD 还会显示**当前视野中心的经纬度**和城市名（否则"到底动没动"无法自证）。
- **无人机外形随型号变化**：以前三种机型共用一套模型，看板上分不出"哪架是重载机"。
  现在轻量机是四旋翼、中型机是六旋翼、重载机是八旋翼（机身更厚、宽起落架、双货舱、橙色装饰），
  几何体在 `drone/droneGeometry.ts` 里按 `modelCode` 参数化，机队页的 3D 建模抽屉与态势地图的
  立体视图共用同一份；遥测帧为此新增 `modelCode` 字段。
- **全国多城市演示**：种子数据与自动补单覆盖**上海 / 北京 / 深圳 / 成都**四个城市集群
  （26 架无人机、14 个空域（含 4 个**建筑障碍**：高楼楼群 0~180m 不可穿越）、**40 座全国充电站**、12 张跨城订单），四个城市同时起飞；
  地图在低缩放下按 0.5° 网格聚类，**每个城市各出一个"作业区"标记**（含城市名与在飞架数），点击即缩放到该城市机队。
- **地图上的地名按缩放分级显隐，并且"放大到哪就看到哪一级的边界"**：地图上真实存在的约束是
  可用的屏幕面积 —— 34 个省级名称 + 几十个城市名常驻显示，缩到全国就是一团黑块。
  所以 z < 4 不标城市，4 ≤ z < 7 只标 34 个省会/直辖市/港澳台（含福州、台北），z ≥ 7 再补上
  23 个计划单列市与重要地级市（含深圳、厦门、台中、高雄）；行政区划名称同理，低缩放只标短名
  （长名"内蒙古自治区""新疆维吾尔自治区"先让位，放大后补回）。另外放大到 z ≥ 6（约 500km 视野）
  或把地图**拖**到某个省时，自动判断视野所在省（中心点优先，中心在海上则取视野覆盖率最大的省）
  并加载其市/区县边界（只加载渲染、不飞视野，避免打断用户正在做的缩放），缩回全国尺度再自动退出；
  加载中与拉取失败都会在"行政区划"面板上说明原因（港澳台等区划暂无更细的数据），不再静默无反应。
- **注册无人机时看得到"这架机能飞多远"**：选完机型立即显示只读能力卡 —— 载重、巡航速度、
  电池/能耗，以及满电航程（容量 ÷ 每公里能耗）、**可用往返半径**（扣 25% 安全冗余后往返可覆盖的单程距离）
  与标称最长飞行。数据直接取自已加载的机队列表（响应里本就带机型能力），不额外加接口。
- **空域创建支持地图拾取**，不必手填经纬度：圆形点击设圆心、拖圆心改位置、拖圆边手柄改半径；
  多边形依次点击加顶点、顶点可拖动微调，另有撤销 / 清空重画；已存在的空域以淡色画在图上做参照，
  底部实时显示光标经纬度。表单里的数字输入框保留，用于精确微调，两边双向同步。
  空域分布在全国时拾取器不会把视野拉到国土尺度（那样点不准），而是退回城市级可操作视野。
- **划定空域时看得到"在哪划"**：拾取器和空域总览图都铺**真实地理底图**（省界 + 省市/区县名称 +
  经纬网 + 城市点位），不再是一块纯色。拾取器里的行政图层设为**非交互**（`interactive: false`），
  否则点省面会被它抢去下钻、用户根本没法在地图上选点。
- **表单里的坐标不再要人手工填**：无人机注册的**起降点**与新建订单的**取货点/送货点**都改成
  **地图点选**（`map/PointPickerMap.vue`），点一下就把经纬度填好，拖动标记还能微调；
  数字框保留用于精确到小数点后 6 位。订单表单用「正在拾取」按钮切换取货/送货，另一个点画成参照圆点。
  两张图都把**禁飞区/限飞区/楼群**叠上去做参照 —— 起降点落进禁飞区等于"这架机永远飞不起来"，
  这种事得在点选时看出来，而不是事后从调度失败原因里反推。参照标记一律不可点击：
  地图点击的语义是"把当前点放到这儿"，参照点再抢点击就会出现"想切换却把坐标改掉了"。
- **路径规划真的不是两点直线**：`dev` 默认启用 Python A*（`sky.algorithm.enabled=true`），
  高楼以 `BUILDING` 障碍建模（高度写在 `maxAltitudeM`，可飞过楼顶），航线绕开楼群并做
  **视线法压拐点 + 转弯半径圆角化**。算法侧的栅格只覆盖"航线走廊 ± 2000m"内的障碍物 ——
  早期把四个城市的障碍物全部纳入包围盒，栅格数上亿，直接把服务内存吃到 7GB 后卡死。
- **无人机是真正的四旋翼模型，不是圆点**。整体按航向偏航（机头 SVG 朝上）、
  四个旋翼**转速随速度变化**（悬停慢、巡航快）、机身颜色跟随状态、低电量红色脉冲圈、
  载货时机腹出现货箱；高度同时驱动**图标缩放与机腹阴影的淡出/缩小/错开**。
  位置、航向与**高度**都在客户端做**指数平滑插值**，所以飞机是"沿弧线滑行、还会爬升下降"，
  而不是每秒瞬移；姿态由时序变化反解——**转弯压坡度（协调转弯 tanφ = v·ω/g）、
  爬升抬头、下降低头**，在俯视图里表现为机身的定向透视压缩。每架机还留下点线状的**已飞尾迹**。
- **航线是"飞出来的弧线"，不是折线**。后端 A* 在视线法之后再做**转弯圆角化**
  （40 m 转弯半径的相切圆弧，并用同一张膨胀栅格逐段校验，不安全就退回尖角），
  前端航路折线用 round 线帽/线接头渲染 —— 由于后端 `pointAtDistance` 沿同一条折线参数化，
  **画出来的弧线就是飞机实际飞的轨迹**。
- **实时通道有完整降级链**：WebSocket 失败 → 指数退避重连（上限 15s）→ 连续失败 3 次自动切 REST 轮询，
  并给出黄色横幅提示。地址用 `location.host` 拼接，开发走 Vite 代理、生产走 Nginx，前端代码零改动。

> 中国地图数据（`frontend/public/geo/china.json`）**不入库**：`pnpm install` 会通过 `postinstall`
> 自动下载一次，也可手动 `pnpm run fetch:geo`。来源与许可说明写在
> [`frontend/scripts/fetch-china-geo.mjs`](frontend/scripts/fetch-china-geo.mjs) 头部；没下载成功也不会崩，
> 只是退化为纯程序化底图并在 HUD 上提示。

正式控制台之外还保留了 `tools/dashboard.html` —— 一个零构建的备用调试页（原生 WebSocket + Leaflet CDN），
在没有 Node 环境、或只想快速确认后端是否正常时非常方便。

前端细节（目录结构、设计取舍、Nginx 部署配置、已知限制）见 [`docs/07-frontend.md`](docs/07-frontend.md)。

## 9. 关键设计决策

这一节列的是"踩过坑才写得出来"的部分，值得单独读。

| 决策 | 原因 |
| --- | --- |
| **硬条件与软条件分离** | "能不能飞"（载重/电量/可达性/距离）在服务层统一过滤并记录淘汰原因；"想派谁"交给可插拔策略。换策略时安全边界不会跟着变 |
| **搜罗式候选预览** | 派单前 `GET /dispatch/candidates` 只返回"扛得动 + 可达（直飞或经停补能）"的入围机，并给出每架机的补能方案；用户看到的不是全机队而是可用运力。预览与真实派单复用同一套 `filterCandidates`，保证"说能飞就真能飞" |
| **无人机 3D 装载演示** | 机队页「3D 建模」用 Three.js 程序化建模（无外部模型文件，离线可用），完整演示待命→下降→抓取货物→锁定→起飞五个阶段 |
| **往返能耗而非单程，且允许补能** | 送完货还要飞回来；但"回不来"要按整条航路算 —— 沿途有站可补就不算回不来。判据从"电量 ≥ 往返能耗"升级为"图上存在一条不超过 3 次补能的可行路径" |
| **批量派单必须独立 Bean** | 同类内 `this.method()` 自调用会绕过 Spring 代理，`@Transactional` 失效 → 懒加载报 `no session` |
| **决策审计用 REQUIRES_NEW** | 派单失败会回滚事务，写在同事务里的审计记录会被一起抹掉——而那正是最需要留痕的时刻 |
| **批次的 limit 限制成功数** | 限制"尝试数"会让几个注定失败的订单永久占满批次，饿死后面的订单 |
| **单拍事务 + 提交后推送** | 事务回滚时前端不应收到"从未发生"的位置；`@TransactionalEventListener(AFTER_COMMIT)` 保证顺序 |
| **`fixedDelay` 而非 `fixedRate`** | 某一拍变慢时 `fixedRate` 会堆积任务，越跑越崩 |
| **算法服务可降级但不撒谎** | 连不上时明确报 503，**绝不退化成直线**（那等于让飞机穿禁飞区）；只有显式关闭算法时才走直线降级 |
| **参数必须自洽** | 机型标称续航与电池容量必须能对上（`容量 ≈ 能耗 × 速度 × 续航`），否则仿真结论与参数表互相矛盾 |
| **演示站点必须在禁飞区外** | 起点落在禁飞区里，规划会直接返回 `start_inside_obstacle` |
| **编号类字段由后端生成** | 机身编号、空域编码这类"必须唯一、必须合规范、注册后不该改"的东西，让人现场编只会带来起名困难和撞号报错；自动编号从 `count()+1` 起**逐个试**而不是直接取数，删除/并发也不会撞号，数据库唯一约束做最后兜底 |
| **能推导的字段不问用户** | 空域严重度按类型给默认值（禁飞区最严、走廊最松），而不是一刀切 HIGH；表单里这类字段标注「可留空」并说明默认行为，确有命名规范要求的运维仍可显式传入 |
| **CSV 带 UTF-8 BOM** | 否则 Excel 打开中文乱码 |
| **不在类型参数上写 `@Valid`** | `List<@Valid X>` 会触发**解析期**错误，javac 随即跳过整个注解处理阶段，Lombok 失效，报出一大片"找不到 builder()"的假象错误 |

## 10. 常见问题

**Q：启动后订单一直派不出去，提示"没有满足条件的无人机"？**
这是**正确行为**。默认演示数据里，部分订单的往返能耗或距离超出机队能力。
调大 `sky.dispatch.search-radius-m`、调小 `min-battery-reserve-pct`，
或给站点补几架飞机即可。每个淘汰原因都写在 `GET /dispatch/decisions?orderId=` 里。

**Q：页面上每个接口都报 500 / "响应不是合法 JSON（HTTP 500）"？**
几乎都是**前端代理连不上后端 8080**：后端没启动，或后端误跑在别的端口（前端 Vite 代理固定转发到 8080）。
现在 Vite 代理会把这种情况返回成带中文指引的 503 JSON，直接照提示做即可：
① 用 `pwsh -File .\start-dev.ps1` 一键启动（最省心）；② 或确认后端在 `backend` 目录 `mvn spring-boot:run`
且监听 8080（`curl localhost:8080/actuator/health`）。后端若在其它端口，可用 `VITE_BACKEND_URL` 让前端代理指过去。

**Q：派单接口返回 503 "无法连接算法服务"？**
说明当前开启了算法服务（`sky.algorithm.enabled=true`）但 Python 没起。
`dev` profile **默认离线降级**（`enabled=false`，走直线航路，派单/仿真照常进行，顶部状态条显示金色「离线降级」）；
只有在 `postgres` profile 或显式打开开关时才需要起 Python：
`cd algorithm-service && uv run uvicorn app.main:app --port 8000`。
用 `GET /api/v1/dashboard/algorithm-health`（含 `enabled`/`available`）可快速确认。

**Q：地图是一片空白 / 什么都没有？**
正式控制台（`pnpm dev`）的底图是**离线程序化生成**的，不需要任何网络地图服务，正常不会空白。
如果确实空白，通常是这三种情况：① 后端没起，页面在等遥测数据（会显示"等待遥测数据…"提示）；
② 浏览器控制台有 JS 报错（把报错发我）；
③ 缩放被拖出了作业区范围（地图已限制在上海一带，可点"刷新"或重新加载页面回到默认视野）。
另：备用调试页 `tools/dashboard.html` 仍然用 Leaflet CDN，离线环境需把 CSS/JS 下到本地再改路径。

**Q：无人机会不会一直是圆点？**
不会。正式控制台里是**四旋翼 SVG 模型**（按航向偏航、旋翼旋转、状态变色、低电量脉冲、载货显示货箱）。
如果看到圆点，说明打开的是备用调试页 `tools/dashboard.html`。

**Q：H2 控制台连不上？**
JDBC URL 是 `jdbc:h2:mem:skydispatch`，用户名 `sa`，密码留空，且必须在 `dev` profile 下。

**Q：换了 JDK 23/24 能编译吗？**
能。`pom.xml` 里 `java.version=21` 会用 `--release 21` 编译到 Java 21 字节码。
但注意 Lombok 需要 1.18.34+ 才支持 JDK 23+（Spring Boot 3.4 已管理为 1.18.36）。

**Q：`mvn` 卡在下载依赖？**
配镜像加速，例如 `~/.m2/settings.xml` 里加阿里云 `central` 镜像。
若在受限环境（不允许写 `~/.m2`），可用仓库内的 `.build/maven-settings.xml`：
`mvn -s ..\.build\maven-settings.xml spring-boot:run`（本地仓库落在 `.build/m2`）。

**Q：前端页面打开是空白 / 接口报 404？**
按顺序检查：① 后端是否已在 8080 启动（`curl localhost:8080/actuator/health`）；
② 前端是否用 `pnpm dev` 启动（Vite 代理只在开发服务器里生效）；
③ 如果直接用了 `pnpm preview`（4173），跨域已由后端 `WebConfig` 放行，但**生产部署必须自己配 Nginx 转发**，
参考 [`docs/07-frontend.md`](docs/07-frontend.md) 第 6 节。

**Q：前端 `pnpm install` 后 `vite` 报 `ERR_MODULE_NOT_FOUND: rollup`？**
pnpm 在部分 Windows 环境下用 junction 建立 `node_modules`，Node 的 ESM 解析器不展开它，
导致从 vite 内部找不到 rollup。项目已在 `frontend/.npmrc` 里配了 `node-linker=hoisted`
（扁平布局、无 junction）来规避；若你手动删过该文件，加回来即可。

**Q：换机型参数后仿真结果很奇怪？**
先检查参数自洽性：`battery_capacity_wh ≈ energy_per_km_wh × cruise_speed_mps × max_flight_min / 60`。
三者矛盾时，仿真的续航校验会和标称参数打架（默认演示数据已经按这个公式对齐）。

**Q：能不能不用 Python，只跑 Java？**
可以。设 `sky.algorithm.enabled=false`，路径规划会退化为两点直线（控制台会打警告），
用于纯 Java 侧的开发调试。**生产环境绝不要这样跑**——直线会穿过禁飞区。

**Q：仿真跑太快/太慢？**
调 `sky.simulation.tick-ms`（每拍真实毫秒）与 `sky.simulation.speed-factor`（仿真倍速）。
默认 1000ms / 8.0，即 1 秒真实时间推进 8 秒仿真时间。

**Q：无人机的"爬升/下降"是怎么来的？能调吗？**
能。后端不是让飞机瞬间贴到巡航高度，而是按**飞行剖面**推进：起飞加速 → 爬升 → 巡航 → 下降 → 减速降落，
去程与回程各算一次。爬升/下降的**水平过渡距离**由垂直速率换算而来
（爬 80 m 用 4 m/s 需要 20 s，这 20 s 里以巡航速度前飞 ≈ 300 m，就是它开始平飞的位置）。
可调参数在 `application.yml` 的 `sky.flight` 下：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `climb-speed-mps` | 4.0 | 爬升速率，决定爬升过渡区有多长 |
| `descent-speed-mps` | 3.0 | 下降速率（比爬升略慢，接近真实多旋翼策略） |
| `speed-ramp-m` | 80.0 | 起降加减速的水平过渡距离 |

## 12. 已知限制与演进

MVP 阶段的自觉取舍（都不是"忘了做"，而是**为了 7 天能演示而刻意延后**）：

| 限制 | 影响 | 演进方向 |
| --- | --- | --- |
| 冲突只**检测**不**消解** | 告警多但不影响任务推进 | 加高度层分配 + 调速/等待/改航路 |
| 所有飞机同高度（默认 80m） | 机-机冲突偏多 | 引入高度层 |
| 返航终点是取货点，不单独规划回机巢航路 | 回程距离与真实有偏差 | 规划"取货点→机巢"第二段航路 |
| 未建模"当前位置→取货点"的空载段 | 派单时低估实际能耗 | 把当前位置作为 A* 起点 |
| 派单事务内发起 HTTP 调用 | 长事务占用数据库连接 | 拆成"选候选 / 事务外规划 / 落库确认"三段 |
| 订单号用"当日计数 + 1" | 并发下单可能撞号 | 改数据库序列 |
| 冲突去重指纹存在进程内存 | 多实例部署会重复告警 | 指纹移到 Redis |
| 仿真运行单实例 | 无法并行对比多套策略 | 每 run 独立引擎上下文，做 A/B 沙盘 |

完整演进路线见 [`docs/01-architecture.md`](docs/01-architecture.md) 第 7 节。
